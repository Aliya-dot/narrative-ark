# 测试矩阵与第一可交付验收

本文件定义叙界桌面端、Android 客户端、模型兼容、本地数据、故障恢复和升级兼容的最低测试范围。机器可读清单位于 [`test-matrix.json`](../test-matrix.json)，CI 使用 `npm run test:matrix` 防止覆盖项被误删。

## 1. 第一可交付目标

> Windows 安装包和 Android APK 均可安装，能创建项目、调用模型、连续游玩、保存、重开和导出，且全程不依赖自有服务器。

## 2. 平台与显示矩阵

GitHub 的 Windows runner 是安装器代理环境，不等同于 Windows 客户端版本，因此 Windows 10/11 真机验收始终是正式放行条件。

| 平台           | 最低组合                                           | 类型          | 重点                                         |
| -------------- | -------------------------------------------------- | ------------- | -------------------------------------------- |
| Windows 10     | 22H2 x64，1366×768 / 100%，1920×1080 / 125%        | 真机          | 安装、WebView2、窗口控件、文件选择、导出     |
| Windows 11     | 当前稳定版 x64，2560×1440 / 150%，3840×2160 / 200% | 真机          | 高 DPI、升级、重开、SmartScreen 提示         |
| Windows runner | windows-2022、windows-2025                         | 每周自动      | 静默安装、启动、原位升级、卸载、应用数据保留 |
| Android 9      | API 28，360×640                                    | 模拟器 + 真机 | minSdk、紧凑屏、软键盘、后台恢复             |
| Android 当前版 | API 36，412×915 与 1280×800                        | 模拟器 + 真机 | targetSdk、权限、横竖屏、平板布局            |

每个显示组合至少检查：

1. 导航、弹窗、表单、编辑器、游玩输入框不被裁切。
2. 100%、125%、150%、200% 缩放下文字清晰且操作目标可点击。
3. 软键盘出现时 Android 输入框与主要按钮仍可见。
4. 横竖屏切换或窗口缩放后当前编辑内容、滚动位置和游玩状态不丢失。

## 4. 功能旅程

每个平台、每个正式支持的模型至少执行一次：

1. **创建**：选择简单/高级模式，生成完整项目，关闭创建页后项目仍存在。
2. **编辑**：修改项目、角色、世界书，保存后重新进入确认内容一致。
3. **游玩**：从第 0 回合开始，连续完成至少 10 回合；自由输入与预设选项各使用一次。
4. **保存**：创建手动存档，记录回合、地点、属性、任务和最近消息。
5. **重开**：完全退出进程后重新启动，载入同一项目与存档并继续一回合。
6. **导出**：导出项目 JSON/TXT、游戏包或游戏记录；重新导入可导入格式并核对归属关系。

## 5. 故障与恢复矩阵

| 故障           | 注入方式                           | 预期                                           |
| -------------- | ---------------------------------- | ---------------------------------------------- |
| 请求前断网     | 飞行模式/禁用网卡后调用模型        | 显示连接提示；项目与存档不变                   |
| 请求中断网     | 生成过程中断开网络                 | 请求结束为失败；按钮恢复；可重试               |
| 超时           | 使用极短超时或延迟代理             | 显示超时提示；不写入半个回合                   |
| 401/403        | 使用失效测试 Key                   | 显示鉴权提示；错误中不回显 Key                 |
| 429            | 测试网关返回限流                   | 显示限流/额度提示；允许稍后重试                |
| 5xx            | 测试网关返回 503                   | 显示服务异常；稳定数据不变                     |
| 畸形响应       | 返回空正文、截断 JSON、错误字段    | 受控重试；第二次仍失败时保持原数据             |
| 数据库写入失败 | 在事务中注入失败                   | 整体回滚，不出现孤立项目或孤立存档             |
| 数据库恢复     | 导出本地数据、清空测试库、重新导入 | 项目、存档、世界书恢复；API Key 不进入明文备份 |

## 6. 旧版本升级与存档兼容

### 自动验证

- `project-migration*.test.mts`：旧项目结构与部分生成结果迁移。
- `save-migration.test.mts`：旧存档规范化与幂等迁移。
- `project-import-workflow.test.mts`：导入冲突、事务回滚、未来版本拒绝和敏感信息脱敏。
- `windows-release-smoke.ps1`：原位升级与卸载后应用数据保留。

### 每次正式发布前

1. 保存上一正式版 EXE、APK、项目导出包和存档导出包作为只读基线。
2. 使用上一正式版创建项目并游玩至少 3 回合。
3. 原位安装候选版本，不提前卸载旧版。
4. 重开旧项目与旧存档，继续一回合并重新导出。
5. 比较标题、角色、世界状态、回合数、物品、任务和最近消息。
6. Android 在系统升级前后各启动一次；Windows 在 10→11 场景至少做一次跨系统复核。
