## 4. 通过、失败与停止规则

- 状态只允许：`NOT RUN`、`PASS`、`FAIL`、`BLOCKED`。
- `PASS`：真实浏览器操作、界面结果、Console、IndexedDB/文件证据同时满足预期。
- `FAIL`：功能结果错误、出现未解释的 Console error / unhandled rejection、ID 归属错误、回合或已确认内容丢失、失败后产生不应有的写入。
- `BLOCKED`：外部 API、网络或环境阻止执行，且没有形成产品正确或错误的结论；不得记为通过。
- 任一核心用例 `FAIL` 或 `BLOCKED` 后立即停止后续核心用例，先保全证据并评审当前任务。
- 失败或阻断后不得跳过用例，也不得临时修改代码、数据库或配置后继续把同一 Run 记为通过；发生修复或影响结果的环境变更时，原 Run 保持失败/阻断并结束。
- 修复后必须新建 Run ID，从能证明修复且不破坏前序状态的最小边界开始；若修复影响创建、生成、持久化、归属或导出协议，则从 `MVP-00` 重跑全链路。
- 自动检查通过只证明相应自动检查通过，不以源码检查、单元测试或接口模拟替代任何矩阵中的真实浏览器人工步骤。

## 5. 证据目录与命名

建议把验收证据存放在仓库外的本轮专用目录，避免密钥、生成内容和大文件误入 Git：

```text
[EVIDENCE_ROOT]/
└─ MVP-E2E-YYYYMMDD-NN/
   ├─ run.md
   ├─ screenshots/
   ├─ console/
   ├─ idb/
   └─ exports/
```

统一命名：

| 证据           | 文件名格式                                  |
| -------------- | ------------------------------------------- |
| 截图           | `{RUN_ID}_{CASE_ID}_{SEQ}_{STATE}.png`      |
| Console 导出   | `{RUN_ID}_{CASE_ID}_console.log` 或 `.json` |
| IndexedDB 摘要 | `{RUN_ID}_{CASE_ID}_idb-summary.json`       |
| 启动日志       | `{RUN_ID}_server.log`                       |
| 导出文件       | 保留应用原文件名，复制到 `exports/`         |
| 文件校验       | `{RUN_ID}_{CASE_ID}_export-sha256.txt`      |

每条记录至少包含：

```text
Run ID:
Case ID:
状态: NOT RUN | PASS | FAIL | BLOCKED
操作者:
开始/结束时间（Asia/Shanghai）:
提交:
浏览器与版本:
当前 URL:
projectId:
saveId:
回合 before -> after:
关键 updatedAt / settingsVersionNumber:
截图:
Console error 数量及首条错误:
IndexedDB 读数:
导出文件名 / 字节数 / SHA-256:
实际结果:
与预期差异:
备注:
```

ID 记录规则：

- `projectId`：从当前 URL `/editor/{projectId}` 或 `/play/{projectId}` 取得，并与 `projects.id` 交叉核对。
- `saveId`：从 `/play/{projectId}?save={saveId}` 或 `saves` store 取得，并核对 `save.projectId === projectId`。
- 初次试玩在没有既有存档时，预期初始存档 ID 为 `initial_{projectId}`。
- 时间统一记录为带时区的 ISO 8601 值，例如 `2026-07-27T14:30:00+08:00`；同时记录界面显示的本地时间时，不用它替代原始 `createdAt` / `updatedAt`。
- 错误记录包含发生用例、操作序号、时间、当前 URL、首条完整错误信息及 Console error / unhandled rejection 数量；敏感字段仍按 `[REDACTED]` 处理。
- `exports.id` 只记录 ID 与 `projectId`、`format`、`createdAt`，不把它当作下载文件完整性的替代证据。
- 任何截图不得显示 API Key；IndexedDB 摘要不得包含 `configs.apiKey`。

导出文件校验示例：

```powershell
Get-Item -LiteralPath "[EXPORTED_FILE]" | Select-Object Name,Length,LastWriteTime
Get-FileHash -Algorithm SHA256 -LiteralPath "[EXPORTED_FILE]"
```

## 6. 验收后数据保留、清理与恢复

1. 在单轮结论和总控判定完成前，保留专用浏览器配置文件、IndexedDB、Console 日志、截图及原始导出文件，不提前清理失败现场。
2. 先把最终脱敏 IndexedDB 摘要、Console 日志、截图、导出文件属性和 SHA-256 保存到本轮证据目录，再执行任何清理。
3. 证据目录保留到稳定 MVP 正式完成评审结束；若评审要求延期或复核，按评审决定继续保留。证据不得进入 Git，也不得包含密钥或敏感认证信息。
4. 评审允许清理后，优先通过应用 UI 删除验收项目及其存档并核对归属；随后删除活动 API 配置，最后清理该专用 Origin 或直接删除专用浏览器配置文件。
5. 不对个人正式项目执行清理，不用 Git 回滚标签恢复浏览器数据，也不把验收数据复制回个人浏览器配置文件。
6. 若要复验，使用新的 Run ID，并按 `MVP-00` 重新建立干净的专用验收环境；不得复用已判定失败且被人工改写的数据冒充新一轮初始状态。
