# 稳定 MVP 核心闭环人工验收用例矩阵

配套基线：[`STABLE_MVP_ACCEPTANCE_BASELINE.md`](./STABLE_MVP_ACCEPTANCE_BASELINE.md)

## 1. 总矩阵

| Case ID | 闭环节点       | 核心断言                                                 | 必备证据                                                      | 状态    |
| ------- | -------------- | -------------------------------------------------------- | ------------------------------------------------------------- | ------- |
| MVP-00  | 验收前置       | 基线、浏览器、空站点数据、API 连接和下载目录均满足条件   | 基线命令输出、环境记录、脱敏 API 成功截图、空库摘要           | NOT RUN |
| MVP-01  | 创建项目       | 固定输入经 UI 保存为创建草稿，未出现错误或跨项目数据     | 创建确认截图、URL、`drafts` 摘要                              | NOT RUN |
| MVP-02  | AI 生成        | 分阶段生成全部完成，落入编辑页，正式项目唯一且可读       | 完成截图、`projectId`、生成请求结果、`projects`/`drafts` 摘要 | NOT RUN |
| MVP-03  | 人工编辑       | 编辑标记仅在显式保存后持久化，刷新后仍存在               | 保存前后截图、设定版本、`updatedAt`                           | NOT RUN |
| MVP-04  | 首次试玩       | 从编辑页进入试玩，项目归属正确并建立唯一初始存档         | 试玩截图、`projectId`、`saveId`、turn 0 摘要                  | NOT RUN |
| MVP-05  | 连续游玩       | 连续 3 回合均成功、顺序正确、同一存档自动保存            | 回合 1/2/3 截图、Console、逐回合存档摘要                      | NOT RUN |
| MVP-06  | 显式保存       | 快速保存成功且不新建、不串改、不降低当前进度             | 保存提示截图、保存前后 ID/turn/`updatedAt`                    | NOT RUN |
| MVP-07  | 关闭并重新打开 | 关闭页面后用同一浏览器重开，首页与试玩恢复同一项目和存档 | 关闭前记录、重开首页与试玩截图、ID/turn 对照                  | NOT RUN |
| MVP-08  | 继续试玩       | 重开后再完成 1 回合，继承前 3 回合且写入同一存档         | 第 4 回合截图、存档摘要、Console                              | NOT RUN |
| MVP-09  | 导出           | 导出当前游戏得到可解析、归属一致、回合一致的 v2 游戏包   | 文件、大小、SHA-256、脱敏结构摘要、`exports` 记录             | NOT RUN |

执行顺序固定为 `MVP-00` → `MVP-09`。任一项未通过时停止，不执行下一项。

每个用例只有在其前置用例为 `PASS` 时才可开始。用例标记 `FAIL` 或 `BLOCKED` 后，本轮所有后续用例保持 `NOT RUN`，不得标为通过。

## 2. 详细用例

### MVP-00 验收前置

**前置条件**

- 当前操作者已阅读配套基线文档，尚未开始创建或游玩验收项目。
- 仓库、浏览器、API 账户和仓库外证据目录可用。

**操作**

1. 记录 Run ID、提交、Node.js、npm、浏览器版本、视口、时区和下载目录。
2. 核验当前提交及 `data-safety-complete-20260727^{}`。
3. 启动唯一开发服务器并访问 `http://localhost:3001`。
4. 清理该 Origin 的站点数据后刷新，确认无项目、存档、草稿、导出记录。
5. 在设置页填写本轮 API 配置，保存并执行“测试连接”。
6. 保持 Console Preserve log 开启，从此不再清理站点数据或 Console。

**预期结果**

- 得到一个可复现、与个人正式数据隔离、能够开始创建项目的真实浏览器环境。

**通过条件**

- Git 记录清楚且标签解析到固化提交。
- 首页可用；数据库为 `narrative-ark` v3；核心业务 stores 初始为空。
- `configs.id = "active"` 且连接测试成功；脱敏摘要中无 API Key。
- 专用下载目录为空；Console 没有 error 或 unhandled rejection。

**证据**

- `MVP-00` 环境记录。
- 首页、设置连接成功、Application/IndexedDB 空业务表截图。
- 脱敏 IndexedDB 摘要与 Console 导出。

**失败/阻断与停止**

- Git 或标签不符、站点数据不能确认为空、API 连接未成功、证据可能泄露敏感信息时记为 `FAIL` 或 `BLOCKED`。
- 立即停止，本轮不得开始 `MVP-01`。

### MVP-01 创建项目

**前置条件**

- `MVP-00 = PASS`，同一浏览器配置、Origin、API 配置和 Run ID 保持不变。
- 除 `configs.id = "active"` 外，核心业务 stores 仍为空。

**操作**

1. 从首页点击“创建文游”，选择“简单模式”。
2. 严格填写基线文档中的固定测试项目输入。
3. 提交并在最终确认框中点击“开始分阶段生成”。
4. 记录进入生成页后的 URL 和草稿 ID；此时不进行其他导航。

**预期结果**

- 固定输入通过真实 UI 形成唯一创建草稿，并进入对应生成页，尚未提前创建试玩存档。

**通过条件**

- 所有固定输入显示正确，无表单校验错误。
- 只产生本项目的创建/生成草稿；没有正式游戏存档。
- URL 中的 ID 与草稿记录一致，无第二个同名草稿。
- Console 无 error；没有失败提示。

**证据**

- 填写完成截图、生成确认截图、生成页初始截图。
- `drafts` 仅包含相关 ID、`updatedAt` 和阶段摘要的脱敏记录。

**失败/阻断与停止**

- 表单无法提交、ID 不一致、出现重复草稿/正式存档、固定输入丢失或出现未解释错误时记为 `FAIL`；外部环境使步骤无法完成时记为 `BLOCKED`。
- 立即停止，本轮不得开始 `MVP-02`。

### MVP-02 AI 生成

**前置条件**

- `MVP-01 = PASS`，当前位于该草稿的生成页。
- API 配置、模型、浏览器、Origin 和 Run ID 未改变。

**操作**

1. 在生成页等待所有分阶段请求自然完成，不刷新、不重复点击、不改配置。
2. 确认应用自动进入 `/editor/{projectId}`。
3. 记录 `projectId`、项目标题、`createdAt`、`updatedAt`、当前设定版本。
4. 检查生成草稿是否按正常完成路径清理。

**预期结果**

- AI 分阶段生成形成唯一正式项目，项目可实际打开进入编辑页，而不只是页面显示“完成”。

**通过条件**

- 所有阶段成功，页面明确提示包体生成完成并进入编辑页。
- `projects` 中恰有一个固定标题项目，`projects.id === URL projectId`。
- 项目结构可被编辑页完整读取，无空白页、错误态或重复项目。
- 正常完成后不存在会再次恢复同一生成任务的残留草稿。
- 尚未产生试玩存档；Console 无 error。

**证据**

- 生成阶段完成与编辑页首屏截图。
- 分阶段请求的状态摘要（不记录请求密钥或 Authorization）。
- `projects`、`drafts`、`saves` 脱敏摘要。

**失败/阻断与停止**

- 任一阶段失败、仅显示完成但项目打不开、项目重复/结构不可读、错误被当作成功或生成归属异常时记为 `FAIL`；API/网络中断且无产品结论时记为 `BLOCKED`。
- 立即停止，本轮不得开始 `MVP-03`。

### MVP-03 人工编辑

**前置条件**

- `MVP-02 = PASS`，当前已打开唯一正式项目的编辑页。
- 记录编辑前 `projectId`、`updatedAt`、`settingsVersionNumber` 和开场剧情原文摘要。

**操作**

1. 在编辑页打开“开场剧情”模块，在文本末尾追加 `【MVP人工编辑标记】`。
2. 保存前截图并确认尚未出现保存成功提示。
3. 点击“保存”，等待成功提示完成。
4. 记录项目 `updatedAt`、`settingsVersionNumber`；刷新编辑页。

**预期结果**

- 人工标记只在显式保存后进入正式项目，刷新后仍存在，并能由后续首次试玩直接验证生效。

**通过条件**

- 保存前，IndexedDB 正式项目内容未出现人工编辑标记。
- 点击保存后出现成功提示，`updatedAt` 单调增加，项目 ID 不变。
- 刷新后标记仍存在且只有一份，其他固定内容没有被意外改写。
- 没有生成存档；Console 无 error。

**证据**

- 保存前、成功提示、刷新后三张截图。
- 保存前后项目脱敏摘要和设定版本号。

**失败/阻断与停止**

- 未点击保存即写入正式项目、保存后刷新丢失、标记重复、项目 ID 改变、其他内容意外改写或出现错误时记为 `FAIL`；环境阻止核对时记为 `BLOCKED`。
- 立即停止，本轮不得开始 `MVP-04`。

### MVP-04 首次试玩

**前置条件**

- `MVP-03 = PASS`，编辑页刷新后仍显示唯一人工编辑标记。
- 当前项目尚无存档，已记录正式项目 ID。

**操作**

1. 从编辑页点击“开始游玩”。
2. 等待试玩界面和开场内容完整显示。
3. 记录 URL、项目 ID、存档 ID、回合、开场最后一条叙事消息 ID。

**预期结果**

- 编辑后的项目被成功打开为第 0 回合试玩，建立唯一正确归属的初始存档，开场内容体现已保存的人工编辑。

**通过条件**

- URL 为 `/play/{projectId}`，项目 ID 与 `MVP-02` 相同。
- 初次载入为第 0 回合，并存在且仅存在一个属于该项目的初始存档。
- 初始存档预期 `saveId = initial_{projectId}` 且 `save.projectId === projectId`。
- 开场内容可见且包含且仅包含一次 `【MVP人工编辑标记】`，主角状态和项目标题可见；Console 无 error。

**证据**

- 第 0 回合完整试玩界面截图。
- `projects` 与 `saves` 的 ID、归属、turn、消息数、`updatedAt` 摘要。

**失败/阻断与停止**

- 项目打不开、人工编辑未在试玩中生效、初始存档缺失/重复/串项目、回合不是 0 或出现错误时记为 `FAIL`；环境阻止加载时记为 `BLOCKED`。
- 立即停止，本轮不得开始 `MVP-05`。

### MVP-05 连续游玩

**前置条件**

- `MVP-04 = PASS`，当前为第 0 回合，项目和初始存档归属已核对。
- API 配置仍可用，固定行动文本已经准备好。

**操作**

1. 依次提交固定行动 1、2、3；每次必须等待当前 AI 回复及“本回合已自动保存”后再提交下一次。
2. 每回合记录玩家消息 ID、叙事消息 ID、turn、`updatedAt` 和当前存档 ID。
3. 第 3 回合完成后检查剧情区包含三组按顺序排列的玩家行动和 AI 回复。

**预期结果**

- 同一存档连续完成三个成功回合，每个回合只增长一次并自动持久化，前序剧情不被覆盖。

**通过条件**

- turn 严格按 `0 → 1 → 2 → 3` 增长，不跳号、不重复。
- 三次操作全程使用同一 `projectId` 和 `saveId`。
- 每回合成功后 `updatedAt` 单调增加，刷新当前页面后仍为相同回合和内容。
- 玩家行动顺序正确，上一回合结果没有被下一回合覆盖。
- Console 无 error；失败请求没有被界面当作成功回合。

**证据**

- 第 1、2、3 回合完成截图。
- 每回合存档脱敏摘要；第 3 回合后的 Console 导出。

**失败/阻断与停止**

- 任一请求失败却增加回合、回合跳号/重复、存档 ID 改变、历史丢失、刷新后回退或出现错误时记为 `FAIL`；API/网络中断且未形成产品结论时记为 `BLOCKED`。
- 立即停止，本轮不得开始 `MVP-06`，不得跳过失败回合继续发送后续行动。

### MVP-06 显式保存

**前置条件**

- `MVP-05 = PASS`，当前为第 3 回合且三个成功回合均已自动持久化。
- 已记录保存前项目 ID、存档 ID、turn、`updatedAt`、消息数和历史长度。

**操作**

1. 记录当前 `saveId`、turn、`updatedAt`、消息数和历史长度。
2. 打开存档管理，点击“快速保存当前进度”。
3. 等待“当前进度已保存”提示，再读取同一存档。

**预期结果**

- 显式保存更新当前存档而不创建新存档，不改变归属、回合或已经确认的剧情状态。

**通过条件**

- 保存成功；`saveId`、`projectId`、turn、消息内容和历史顺序不变。
- `updatedAt` 增加，`saves` 总数不因快速保存增加。
- 没有生成跨项目存档或空存档；Console 无 error。

**证据**

- 保存前状态、成功提示、保存后存档列表截图。
- 保存前后 IndexedDB 对照摘要。

**失败/阻断与停止**

- 保存失败、创建额外存档、改变项目/存档 ID、回合或内容、`updatedAt` 不增加、出现跨项目记录或错误时记为 `FAIL`；环境阻止保存时记为 `BLOCKED`。
- 立即停止，本轮不得开始 `MVP-07`。

### MVP-07 关闭并重新打开

**前置条件**

- `MVP-06 = PASS`，关闭前状态与 Console 证据已保存。
- 当前浏览器使用普通专用配置文件，开发服务器保持运行。

**操作**

1. 记录关闭前 URL、`projectId`、`saveId`、turn、最后一条消息 ID 和 `updatedAt`。
2. 关闭该 Origin 的全部页面和 DevTools 窗口，然后完全退出浏览器进程；保留开发服务器，不清理浏览器数据。
3. 重新启动浏览器，用同一普通浏览器配置文件打开 `http://localhost:3001`；这一步不得用刷新、软导航或仅关闭单个页面代替。
4. 在首页确认项目卡与“继续”入口显示第 3 回合，点击继续。
5. 记录重开后的 URL 与 IndexedDB 状态。

**预期结果**

- 浏览器完全退出并重启后，首页找到原项目，并通过继续入口加载原项目所属的原存档，而不是最新但不相关的记录。

**通过条件**

- 首页显示同一固定标题项目，且继续入口为第 3 回合。
- 进入试玩后 `projectId`、`saveId`、turn、最后一条消息 ID 与关闭前一致。
- 开场中的人工编辑标记仍存在；已确认三回合内容均可见。
- 重开过程没有创建第二项目、第二初始存档或重置进度。
- Console 无 error。

**证据**

- 关闭前、重开首页、重开试玩三张截图。
- 关闭前后项目/存档 ID 与计数对照。

**失败/阻断与停止**

- 仅刷新而未完整重启浏览器时本用例无效；重开后项目/存档归属、ID、turn 或最后消息不符，出现新初始存档、进度重置或错误时记为 `FAIL`；浏览器/环境无法重开时记为 `BLOCKED`。
- 立即停止，本轮不得开始 `MVP-08`。

### MVP-08 继续试玩

**前置条件**

- `MVP-07 = PASS`，重开后已核对同一 `projectId`、`saveId` 和第 3 回合状态。
- API 配置仍然可用，前三回合内容完整。

**操作**

1. 在重开的试玩页提交固定“重开后行动”。
2. 等待 AI 回复与自动保存完成。
3. 记录新的 turn、消息 ID、`updatedAt` 和存档 ID。

**预期结果**

- 新行动从原存档第 3 回合继续为第 4 回合，沿用原剧情与状态，不新建或重置存档。

**通过条件**

- turn 从 `3 → 4`，同一项目和存档 ID 保持不变。
- AI 回复承接已有上下文；前三回合和人工编辑内容没有丢失。
- 自动保存完成，刷新后仍为第 4 回合。
- Console 无 error。

**证据**

- 行动提交前和第 4 回合完成截图。
- 第 4 回合存档摘要与 Console 导出。

**失败/阻断与停止**

- 从错误存档继续、回合未按 `3 → 4`、创建新存档、上下文/状态重置、刷新后丢失或错误请求被算作成功时记为 `FAIL`；API/网络阻止完成且无产品结论时记为 `BLOCKED`。
- 立即停止，本轮不得开始 `MVP-09`。

### MVP-09 导出

**前置条件**

- `MVP-08 = PASS`，当前同一存档已稳定持久化到第 4 回合。
- 本轮专用下载目录为空或已记录现有文件清单，具备只读解析 JSON 和计算 SHA-256 的条件。

**操作**

1. 在第 4 回合试玩页打开导出菜单，点击“导出当前游戏”。
2. 等待成功提示，在专用下载目录找到本轮新文件。
3. 记录文件名、字节数、修改时间和 SHA-256。
4. 以只读方式解析 JSON，并记录顶层字段、项目/存档 ID、回合和归属。
5. 检查 IndexedDB `exports` 新记录。

**预期结果**

- 得到一个可打开、可解析、无敏感认证信息且与当前项目/存档/回合完全一致的 v2 游戏包。

**通过条件**

- 文件名为 `MVP核心闭环-20260727-01-第4回合-游戏包.json`，文件非空且 JSON 可解析。
- 顶层 `format === "narrative-ark-game"`、`version === 2`，并有合法 `exportedAt`、`project`、`save`。
- `project.id` 等于全链路 `projectId`；`save.id` 等于当前 `saveId`；`save.projectId === project.id`；`save.turn === 4`。
- 导出项目的 `openingScene` 包含且仅包含一次 `【MVP人工编辑标记】`，存档包含连续四回合结果。
- 导出包不含 `apiKey`、Authorization 或活动 API 配置。
- `exports` 新增一条 `format = "game-bundle"` 且 `projectId` 正确的记录。
- Console 无 error。

**证据**

- 导出操作与成功提示截图。
- 原始导出文件、文件属性、SHA-256。
- 不含生成正文和密钥的结构摘要，以及 `exports` 记录摘要。

**失败/阻断与停止**

- 仅出现下载提示但文件缺失/为空/不可解析、格式版本错误、项目或存档归属不符、turn 不是 4、核心内容缺失、包含敏感认证信息、`exports` 记录不符时记为 `FAIL`；文件系统环境阻止核对时记为 `BLOCKED`。
- 本用例失败或阻断时整轮闭环不得标为通过，不再执行任何后续验收或清理现场。
